# SELEN AI و یکپارچه‌سازی پیام‌رسان (فاز ۲ — پیاده‌سازی شد)

## SELEN (§21–§22, §61–§62) — READY

```
Application → SELEN AI Service (backend/app/ai) → AiProvider Interface
                                                   ├─ RuleBasedProvider (پیش‌فرض، آفلاین، قطعی)
                                                   └─ OpenAiCompatProvider (SELEN_PROVIDER=openai_compat)
```

- **استقلال Provider (§62):** انتخاب فقط با متغیرهای محیطی `SELEN_PROVIDER` / `SELEN_API_URL` / `SELEN_API_KEY` / `SELEN_MODEL`؛ بدون تغییر کد کسب‌وکار.
- **Resilience:** هر خطا در Provider بیرونی به‌صورت شفاف به موتور قوانین داخلی Fallback می‌شود؛ توصیه هرگز مسدود نمی‌شود.
- **محدودیت نقش (§21):** SELEN فقط Advisor است؛ دسترسی با Permission `selen.use` و ثبت در Audit؛ هیچ عملیات حساسی اجرا نمی‌شود و **توصیه AI ≠ تصمیم نهایی (§22)** — در UI همواره Disclaimer نمایش داده می‌شود.
- **ورودی:** تجهیز + شرح مشکل (+ متن/صوت/عکس در توسعه بعدی)؛ **خروجی §22:** احتمال خرابی، موارد بررسی، اقدامات به ترتیب، قطعات احتمالی، ابزار، نکات ایمنی — با توجه به بحرانی‌بودن تجهیز، سوابق نت و PMهای عقب‌افتاده.
- **§24:** `/api/selen/spare-suggestions` قطعات را بر اساس موجودی/حد سفارش، اهمیت تجهیز مرتبط، زمان تأمین، نبودِ جایگزین و درجه اهمیت امتیازدهی می‌کند؛ Add/Edit/Delete/Override برای کاربر مجاز محفوظ است.

## Messenger داخلی (§32) — READY (In-App)
گفتگوی درون‌برنامه‌ای مستقل از هر سرویس بیرونی: شروع مشاوره با نقش «مدیر فنی»، پیام‌رسانی دوطرفه Real-Time، نشان خوانده‌نشده. پیام صوتی/تماس در توسعه بعدی همین هسته اضافه می‌شود؛ کانال‌های بیرونی فقط اعلان یک‌طرفه (§32B).

## مشاوره داخلی و Messenger (§32, §32B)
- هسته In-App (متن/صوت/تماس) در فاز ۲ روی همان Event Bus ساخته می‌شود و به سرویس بیرونی وابسته نیست.
- اتصال بیرونی فقط کانال **اعلان یک‌طرفه** است (نه پل چت/تماس) و از طریق `Messenger Notification Service` (رابط) به Provider Adapterها وصل می‌شود؛ Fallback به In-App/ایمیل تضمین می‌شود؛ اتصال شخصی فقط با تأیید خود کاربر.

## وضعیت مستند Messengerها — بررسی به‌روز (2026-08-17، طبق §32B)

| کانال | اعلان یک‌طرفه | چت دوطرفه Bot | تماس صوتی/تصویری |
|---|---|---|---|
| **بله (Bale)** | **READY** — Bot API رسمی مستند در docs.bale.ai (الزام به استفاده انحصاری از API رسمی در قوانین بله) | محدود به تعامل Bot | **NOT SUPPORTED** |
| **روبیکا (Rubika)** | **READY** — برخلاف زمان نگارش سند کارفرما، اکنون Bot API رسمی با SDK رسمی «Rubka» (منتشرشده ژوئن ۲۰۲۶، مستندات rubka.ir) وجود دارد | پیام/مدیا/کی‌پد از طریق Bot | **NOT SUPPORTED** |

**نتیجه برای Scope فاز ۲:** ارسال Notification یک‌طرفه به هر دو کانال از طریق `Messenger Notification Service` (رابط انتزاعی §32B) قابل‌تحویل است؛ تماس صوتی/تصویری فقط In-App پیاده می‌شود. آداپتورها در فاز ۲ اضافه می‌شوند؛ هسته فاز ۰/۱ هیچ وابستگی به این سرویس‌ها ندارد (Fallback Rule برقرار است).
